## 一、架构与技术决策（ADR）

**Q1：为什么选 httpx 而不是 requests？**

A：原生同步/异步双接口，`timeout` 是一等参数；`httpx.MockTransport` 可直接注入测试响应，
不需要 monkeypatch 网络栈。见 `specs/design.md` ADR-001，落地在 `src/daily_report/net.py`。

**Q2：为什么用标准库 sqlite3 而不是 SQLAlchemy？**

A：数据量远低于 SQLite 上限（日增千条量级），零额外依赖，部署即复制文件；
显式 SQL 便于逐条审查参数化。见 ADR-002。SQL 全部集中在
`src/daily_report/storage/repository.py`，由 `test_architecture.py` 自动检查。

**Q3：为什么要端口适配器，直接 if mock 不好吗？**

A：内嵌分支会让真实与模拟逻辑互相污染，无法独立测试。现在
`collectors/base.py` 定义 Protocol，真实与 Mock 共享契约，配置一行切换。
见 ADR-004 与 `config.py` 的 `source_mode`。考勤那次变更正好验证了这个设计的价值：
新增一个 Protocol 即可，既有三源零改动（ADR-005）。

## 二、安全

**Q4：令牌怎么管理的？会不会被带进仓库？**

A：唯一读取点是 `config.py:50` 的 `load_settings`；`Settings` 对
`github_token`、`feishu_app_secret`、`smtp_password` 设了 `repr=False`，
有测试断言 `repr` 不泄露（`test_settings_repr_does_not_leak_secrets`）。
`.env` 在 `.gitignore`，全仓检索无令牌（见 `安全自检记录.md`）。

**Q5：SQL 注入怎么防？**

A：全部 `?` 占位参数化，`test_architecture.py` 检查 SQL 只出现在 `storage/`，
防止有人在别处拼接。检索确认无 `execute(f"..."` 或 `execute(... + ...)`。

**Q6：日志会不会泄露邮箱？**

A：`mask_email` 把 `zhangsan@example.com` 变成 `z***@example.com`；
失败原因只记异常**类型名**（`_safe_reason`），因为异常消息里可能带地址。

## 三、异常处理与降级

**Q7：GitHub 挂了整个流程会中断吗？**

A：不会。`run_daily.py` 对每个采集源单独 `try/except`，失败记入
`RunSummary.failed` 与 `missing_sources`，其余源继续；日报 `note` 标注
"来源缺失：github"。用例 `test_single_source_failure_does_not_abort`。

**Q8：邮件发失败会怎样？**

A：单个收件人失败不中断整批（CR-003）；认证失败则整批立即停止并标记剩余收件人。
日报本身已入库，次日可补推。用例 `test_partial_failure_does_not_stop_batch`
与 `test_auth_failure_stops_whole_batch`。

**Q9：分页取到上限会怎样？**

A：记录 warning（`commit collection truncated at N pages`）并返回已取数据，
调用方可感知。用例 `test_pagination_stops_at_max_pages` 用满页数据验证。

## 四、并发与幂等

**Q10：定时任务重复触发会出两份日报吗？**

A：不会。`run_summaries` 上有部分唯一索引
`(team_id, run_date) WHERE status='success'`（`schema.py:69`），
`run_daily` 入口先 `find_successful_run`，命中则返回 `skipped` 且不写任何记录。
用例 `test_second_run_same_day_is_skipped` 与 `test_ac06_second_run_is_idempotent`。

**Q11：为什么用部分索引而不是表级 UNIQUE？**

A：失败和跳过的运行需要留多条痕迹用于排查；只有"成功的运行"必须唯一。

**Q12：SQLite 并发写怎么办？**

A：开了 WAL（`PRAGMA journal_mode=WAL`），读不阻塞写。本项目是单机单进程定时任务，
`run_daily` 串行调用各层，不存在并发写同一库的场景。

## 五、需求与规范

**Q13：怎么保证代码没跑偏出 proposal 范围？**

A：`tasks.md` 每条任务对应范围条目，`test_regression.py` 按 AC-01~AC-10 逐条验证，
`变更涟漪演练记录.md` 有影响面分析表。考勤变更时先改 proposal 加 R-11，
才允许写代码。

**Q14：现场加一个查询条件，你会改哪里？**

A（示例：按成员查历史日报）：`storage/repository.py` 加一个
`list_reports_by_member(open_id, since, until)` 参数化查询，
`cli.py` 加子命令参数，`tests/test_storage.py` 先加用例。
不需要动采集层与推送层 —— 分层边界决定了改动半径。
