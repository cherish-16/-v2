# AI 使用合规声明

| 项目 | 内容 |
|---|---|
| 项目名称 | 智能日报生成器 v2（Superpowers 工作流驱动） |
| 声明日期 | 2026-11-25 |
| 适用阶段 | 阶段二（第 3–4 周） |

## 1. 使用的 AI 工具

| 工具 | 用途 |
|---|---|
| Claude Code（Agentic CLI） | 需求澄清、规范撰写、任务拆解、代码生成、测试生成、文档撰写 |
| Superpowers 技能库 | 工作流纪律：brainstorming / writing-plans / executing-plans / TDD / verification |

## 2. 四色清单对照

| 等级 | 范围 | 本项目实际使用 | 人工核验 |
|---|---|---|---|
| 绿：可直接用 | 脚手架、注释、文档草稿、测试草稿、报错解释 | `pyproject.toml`、`.env.example`、文档草稿、测试用例草稿 | 已在 AI 使用日志登记 |
| 黄：须审查后用 | 业务逻辑、SQL 与库表设计、接口契约、UML、架构方案 | 全部核心代码、`specs/` 三份规范、5 份 ADR、SQL 表结构 | **全部逐条审查**：每个任务观察 TDD 红灯→绿灯并审 diff；规范由人确认后提交 |
| 红：禁止直接采用 | 认证鉴权核心、隐私数据处理、安全配置、未审查代码 | 令牌管理、日志脱敏、邮箱处置 | 仅作参考，实现与审查由人完成；见 `安全自检记录.md` |
| 黑：学术不端 | 整篇代写、伪造数据、伪造提交历史、日志造假 | **未发生** | 所有数据取自真实命令输出 |

## 3. 人工核验方式

| 环节 | 核验手段 | 证据 |
|---|---|---|
| 代码 | 每个任务先看测试红灯，再审查实现 diff | `docs/工作流执行记录.md` 逐任务红绿记录 |
| 规范 | AI 修改建议经人确认后才提交入 `specs/` | `specs/` 全部提交由人工发起 |
| 测试 | 审查断言是否表达规范意图，拒绝"迁就实现"的断言 | 6 项不一致中 3 项属于"改测试而非改实现"，均记录理由 |
| 数据 | 所有报告数字由命令当场生成 | 各报告附复现命令 |
| 规范漂移 | 脚本 + 人工影响面分析 | `规范漂移自检记录.md`、`变更涟漪演练记录.md` |

## 4. 重要结论的三源核验

| 结论 | 来源一 | 来源二 | 来源三 |
|---|---|---|---|
| 飞书任务/消息/考勤接口字段结构 | 飞书开放平台官方文档 | 代码中 `httpx.MockTransport` 测试夹具 | 采集器字段映射代码 |
| GitHub commits API 分页语义 | GitHub REST 官方文档 | 实现中的 `per_page=100` + 短页停止 | 测试用例 |

## 5. 规范文件的"人类领地"原则

依据指导书第六部分：`specs/` 的修改建议由 AI 提出，**由人确认后提交**。
本项目中：

- `proposal.md` 的范围条目（含"不做什么"5 条）由人确定。
- `design.md` 的 5 份 ADR，AI 列备选项，人做决策。
- 考勤变更时，先由人确认变更单，AI 才修改规范。

## 6. 未使用 AI 的内容

- 项目范围的取舍判断
- 质量数据的真实性核验
- 本声明与审计报告的结论判定
