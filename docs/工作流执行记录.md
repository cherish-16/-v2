## 3. 缺陷与根因记录（systematic-debugging）

| 编号 | 现象 | 最小根因 | 修复 | 防复发 |
|---|---|---|---|---|
| D-01 | Mock 采集器传入 naive datetime 不报错 | 窗口校验写在 `_in_window` 内，无记录时根本不被调用 | 抽出 `_check_window`，在过滤前无条件执行 | `test_naive_datetime_rejected` |
| D-02 | GitHub 采集多余请求 | 只在空页时停止 | 短页即停止 | `test_pagination_stops_at_max_pages`（满页数据） |
| D-03 | 飞书采集返回 0 条 | 测试数据时间戳 `1764072000000` 实为 2025 年 | 改用 `1795600800000`（2026-11-25T10:00Z） | 该用例即防复发 |
| D-04 | `ZoneInfo("Asia/Shanghai")` 抛 `ZoneInfoNotFoundError` | Windows 无系统时区库 | 增加 `tzdata` 依赖 | 依赖已在 `pyproject.toml` |

## 4. 关键裁决

| 编号 | 冲突 | 裁决与依据 |
|---|---|---|
| R-01 | `uv run` 不安装 `optional-dependencies` 导致 ruff 不可用 | 改用 PEP 735 `[dependency-groups]`；这是 uv 的标准做法 |
| R-02 | ruff `UP042` 要求 `StrEnum` | 采纳；行为等价，Python 3.12 已满足 |
| R-03 | 计划的分页截断测试与「短页停止」语义冲突 | 改测试为满页数据；短页停止是 API 标准语义 |
| R-04 | 计划断言单次运行产生 1 份日报 | 实际为个人+团队 2 份；改断言为「重复运行不新增」，这才是幂等的定义 |
| R-05 | `SourceBundle` 是否需要提前容纳考勤 | 预留 `attendance_source=None`，第 4 周再细化为 Protocol |

## 5. 与 SDD 阶段一的方法对比（素材）

| 维度 | 本阶段观察 |
|---|---|
| 规范作用 | 三份规范在任务拆解阶段直接决定测试用例，实现时几乎不需要回头改设计 |
| 任务粒度 | 「一任务一提交」使 16 次提交全部可独立复核；返工只影响单个提交 |
| 测试先行 | 每个任务都观察到红灯，其中 4 次红灯暴露了真实缺陷（D-01~D-04） |
| 主要成本 | 环境搭建（依赖下载、时区库）占比明显高于编码本身 |
